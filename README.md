# Performance Cycle Report Assistant

Generates performance-cycle reports for Technical Writers and Managers using Jira, GitHub, and Slack data with competency frameworks, plus optional Google Drive documents you cite as evidence. Reports are fully formatted and saved automatically.

> **Note:** Atlassian Rovo MCP is automatically configured via the project's `.mcp.json`. GitHub, Slack, and Google Drive are connected as Cursor Plugins (see [Setup Guide](docs/SETUP.md)). Jira and GitHub are required; Slack is an optional automatic source; Google Drive is only used when you explicitly reference a document — it's never searched.

## 🚀 Quick Start

Open Cursor Chat (`Ctrl+L` or `Cmd+L`) and specify the date range, role, and level:

> Specify whether you are an individual contributor or a manager. The IC (Technical Writer) track progresses up to **L4**, while the manager track starts at **L3**. Use "technical writer", "tech writer", "ic", or "individual collaborator" for IC, and "technical writing manager" or "manager" for managers.

**Technical writer examples:**
```
Generate my performance cycle report for 2025-01-01 to 2025-06-30.
I'm a Level 2 IC.
```

```
H1 2025
Tech writer
L3
```

**Technical writing manager examples:**
```
Generate my performance cycle report for 2025-01-01 to 2025-06-30.
I'm a Level 3 Technical Writing Manager.
```

```
Q2 2025, manager, L3
```

> **Note:** Jira, GitHub, and Slack data are fetched automatically (Jira and GitHub are required; Slack is optional). Google Drive is never searched automatically — reference a specific doc/link if you want it fetched as evidence. Your local `context/additional-context.local.md` file (see [Additional Context](#additional-context-local-only) below) is checked automatically on every run — entries are used only if their date(s) fall inside the requested period. You can also mention additional activities directly in your request.

### 📋 Best Practice: Generate Reports by Period

**Recommendation:** Generate reports for **shorter periods** rather than an entire year.

**Why?**
- More manageable data volume
- Clearer quarterly patterns and trends
- Easier to review and validate
- Better alignment with typical performance review cycles

**Suggested periods:**
- **By quarter:** Q1, Q2, Q3, Q4
- **By semester:** H1 (Jan-Jun), H2 (Jul-Dec)
- **By month:** For detailed monthly tracking

**Example:**
Instead of:
```
Generate my report for 2025
```

Do this:
```
Generate my report for Q1 2025
```

> **Tip:** You can still review a full year by generating and reviewing quarterly reports together.

## What you get

Both reports below are generated by default for every request — you don't need to ask for each one separately (unless you explicitly ask for just one). They're saved under `reports/[YYYY]/` (one subfolder per calendar year, based on the period start date):

1. **Work Summary** (`reports/[YYYY]/work-summary-[date-range].md`)
   - Jira metrics (completion rate, carryover analysis, scope creep, avg resolution time, etc.)
   - GitHub metrics (PRs, commits, reviews, review-to-author ratio)
   - Slack metrics (messages/threads, thread-help ratio - if connected)
   - Accomplishments by quarter and area, including any Google Drive docs you cited as evidence
   - Unfinished tasks with semantic blocker analysis and root cause identification

2. **Performance Analysis** (`reports/[YYYY]/performance-analysis-[date-range].md`)
   - Per-competency rating: **Not yet meeting expectations**, **Meets expectations**, **Exceeds expectations**, or **Performing at the next level**
   - Per-dimension rating (IC track), rolled up **conservatively** from its competencies: a dimension only exceeds "Meets expectations" when its competencies are *consistently* above bar, and any below-bar competency caps the dimension at "Meets expectations"
   - Supporting evidence and actionable steps to improve each rating
   - Summary with dimension and competency evaluation overviews and priority development focus

### Regenerating a report

Report filenames are derived from the report type and date range, so asking for the same period again targets the same file. The assistant **overwrites by default**, but asks first if the existing report is more than 7 days old or looks hand-edited. If you choose to keep both, the new one is saved as `[report-type]-[date-range]-[YYYY-MM-DD].md` with the regeneration date appended, and the original is never deleted. Either way, the assistant tells you the full path and whether the file was created, overwritten, or saved alongside.

## Brag documents

Brag docs are short, recurring accomplishment summaries for 1:1s, status updates, and Hibob check-ins. They're a separate request from the performance-cycle reports: asking for a brag doc never generates the Work Summary or Performance Analysis. They use the same sources (Jira, GitHub, Slack, user-referenced Drive docs, and `context/additional-context.local.md`) and also read your Hibob goals from `context/hibob-goals.local.md`.

| Cadence | Use case | Output style |
| --- | --- | --- |
| Daily | Stand-ups, notes | 3–5 bullets |
| Weekly | 1:1s, team sync | 5–10 bullets |
| Biweekly | Sprint reviews | 5–10 bullets with sections |
| Monthly | Monthly check-ins | Sections by project + metrics |
| Quarter | Quarterly reviews | Accomplishments by project + metrics |
| Semester | H1/H2 reviews | Broader summary |

Example requests:

```
Generate my weekly brag doc for last week.
```

```
Brag doc, monthly, February 2026.
Also include:
- Presented at team sync
```

Every brag doc includes:

- **Highlights grouped by project:** each project is the Jira Epic the work rolls up to, shown as `### [Store Framework] 26H2 (EDU-18912)`. Reviews and work without an Epic go under "Other".
- **Competency tags** on each accomplishment, using the keys from your career-path framework (e.g., `content_quality`, `ecosystem_collaboration`). The work is linked to competencies, not rated.
- **Hibob goals update:** for each goal, the KRs that moved in the period, their evidence, the inferred competencies, and a progress note ready to paste into Bob, written in the KR's language.
- **Competency coverage:** how often each competency was tagged in the period.

Brag docs are saved to `reports/[YYYY]/brag/` as `brag-daily-YYYY-MM-DD.md`, `brag-weekly-YYYY-Www.md`, `brag-biweekly-YYYY-MM-DD-to-YYYY-MM-DD.md`, `brag-monthly-YYYY-MM.md`, `brag-quarter-YYYY-Qn.md`, or `brag-semester-YYYY-Hn.md`.

The Work Summary and Performance Analysis read the brag docs whose period overlaps the requested range. Jira and GitHub stay the source of truth: only brag content with no Jira or GitHub match (Slack, extra context) adds new evidence, and competency tags are hints, not ratings.

> **Hibob goals:** copy [examples/hibob-goals.example.md](examples/hibob-goals.example.md) to `context/hibob-goals.local.md` (git-ignored) and keep it in sync with Bob. Without it, the brag doc skips the Hibob section.

## Data Sources

- **Jira** (required): Automatically fetched via Atlassian MCP
  - Connection is validated automatically before report generation
  - If connection fails, see [Setup Guide](docs/SETUP.md) for configuration help
  - Issue types (Epic, New, Update, Review, Task) are detected automatically - see [Metrics Guide](METRICS_GUIDE.md#issue-type-breakdown)
- **GitHub** (required, automatic): Fetched via the GitHub plugin (see [Setup Guide](docs/SETUP.md))
  - Connection is validated automatically before report generation
  - If connection fails, see [Setup Guide](docs/SETUP.md) for configuration help
- **Slack** (optional, automatic): Included if the Slack plugin is connected — messages, threads, and mentoring/help signals (see [Setup Guide](docs/SETUP.md))
- **Google Drive** (optional, **manual/additional-context only**): Never searched automatically — fetches a Doc/Slide/Sheet's content only when you reference it by name or link (see [Setup Guide](docs/SETUP.md))

> Slack is skipped silently if not connected — a failed Jira or GitHub connection blocks report generation. Google Drive has no "connected/not connected" state that affects the run unless you reference a document.

## How agents load this project

Cursor and Claude Code read the same files — there are no tool-specific copies to keep in sync.

| File | What it does | When it loads |
| --- | --- | --- |
| [AGENTS.md](AGENTS.md) | Non-negotiable rules and project layout | Always |
| `.claude/skills/generate-work-summary/SKILL.md` | Work summary structure and metrics | When you ask for a work summary |
| `.claude/skills/generate-performance-analysis/SKILL.md` | Competency evaluation rules | When you ask for a competency evaluation |
| `.claude/skills/generate-brag-doc/SKILL.md` | Brag doc cadences, competency tagging, Hibob goals update | When you ask for a brag doc |
| `.claude/skills/_shared/*.md` | Retrieval and writing rules shared by all three skills | Pulled in by whichever skill is active |

Only `AGENTS.md` is always in context; the skills load on demand based on what you ask for. Cursor reads `AGENTS.md` as a root rule and picks up `.claude/skills/` as [Agent Skills](https://cursor.com/docs/skills) (it loads Claude's skills directory for compatibility), so the legacy `.cursorrules` file is gone and nothing needs to be generated.

### Using this with Claude Code

[CLAUDE.md](CLAUDE.md) is the entry point Claude Code loads automatically; it imports `AGENTS.md` and adds notes on invoking the Skills directly. Project MCP servers live in `.mcp.json`, which Cursor and Claude Code both read — there's no tool-specific copy to keep in sync.

## Privacy

Your performance data stays on your machine. `.gitignore` already excludes the generated `reports/` folder, your personal `context/*.local.md` and `context/additional-context*.md` files, and common secret/token files. Nothing you generate or paste into your local context file is committed by default — but if you fork or reuse this template, re-check `.gitignore` before your first commit, and keep MCP tokens in your **global** `~/.cursor/mcp.json` rather than in this repo.


## Additional Context (local only)

Each Technical Writer can keep a personal `context/additional-context.local.md` file to track evidence that isn't captured by the automatic Jira/GitHub/Slack retrieval — e.g., issues opened on repos outside the indexed scope, mentoring, presentations, strategy work, or **Google Drive documents** (Docs/Slides/Sheets) you want cited as evidence. This file (and any `context/*.local.md` or `context/additional-context*.md` file) is **git-ignored** and stays on your machine only, just like the generated `reports/` folder.

This file is checked automatically on every report request — you don't need to mention it. The assistant keeps only the entries whose date(s) fall inside the requested period (e.g., an entry dated 2026-06-19 is skipped when you ask for a 2025 report) and folds the rest into the relevant work areas/competencies alongside the automatically retrieved data. You can also paste entries directly in your chat request. For Google Drive, either list the doc's link/title in this file or paste the link directly in your chat request — the assistant only fetches a Drive doc when you name it; it never searches Drive on its own.

> **Get started:** See [examples/additional-context.example.md](examples/additional-context.example.md) for the entry template and sample entries. Copy it to `context/additional-context.local.md` to start your own.

## Customization

Every change is made in one place and picked up by both Cursor and Claude Code — there's nothing to regenerate.

- Replace competency frameworks: `context/technical-writer-career-path.json` (writers) or `context/technical-writing-manager-career-path.json` (managers).
- Adjust report structure and metrics: `.claude/skills/generate-work-summary/SKILL.md`, `.claude/skills/generate-performance-analysis/SKILL.md`, and `.claude/skills/generate-brag-doc/SKILL.md`.
- Tweak JQL filters, status normalization, or work-area clustering: `.claude/skills/_shared/data-collection.md`.
- Change tone, output location, or the report regeneration policy: `.claude/skills/_shared/writing-standards.md`.
- Change the always-on rules or project layout: `AGENTS.md`.
